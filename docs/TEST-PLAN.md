## .12 storage fallback / SD故障紧急版

Compiled and packaged only; no functional or physical tests were run. Latest supplied evidence says SD remains unavailable after replacement (FatFs FR_NO_FILESYSTEM; earlier post-format FR_DISK_ERR). The user reports exFAT or another format on the replacement card. This build has `FF_FS_EXFAT=0` and supports FAT12/16/32 only; exFAT can explain that card's mount error, but not all earlier I/O failures. Previous SD successes do not establish recovery. Do not automatically format original cards or unknown internal contents.

1. Without SD, boot and verify internal-library notice, create/save/read/play/style/copy/reorder/delete of temporary manuscripts over HTTP and BLE. Reboot twice and compare text, IDs, styles and order. Capture `storageBackend/storageGeneration/internalTotalBytes/internalAvailableBytes/internalError` and startup logs.
2. With a backed-up FAT32 test card, explicitly reread/switch to SD. Use distinct text with the same title in each backend, switch both ways and verify isolation and retention. Old open editors and queued commands must reject cross-backend writes and keep drafts.
3. Reproduce the reported mount failure only with test cards. Record actual computer-reported filesystem/partition/capacity and FatFs errors. The controller must remain usable via internal storage. Unknown occupied internal partitions must be refused without formatting; report this limitation rather than erasing them.
4. Fill only a disposable internal test library to the reported limit. A failed write must preserve previous data. Test controlled interruption during a temporary write, reboot and verify journal recovery. Delete only your test manuscripts afterwards.
5. Verify local-BIN OTA without SD and physical-SD update refusal without SD; preserve library and settings. Do not count manifest fetch or Demo rendering as firmware installation.

The existing storage data partition is 4,128,768 bytes (3.9375 MiB). Filesystem capacity is smaller; writes use at most 70% and reserve an additional 64 KiB for recovery. Maximum manuscript size remains 8192 UTF-8 bytes. Actual free capacity requires hardware observation. The partition is initialised only if fully erased, otherwise a matching application marker is required. SD and internal manuscripts are never merged automatically. Demo: `/console.html?storage=internal`.

## .11 targeted checks / 本版针对性检查

On a test device with backed-up network settings, let an unavailable test Wi-Fi connection fail. The screen must return directly to step 1, hotspot connection, without a standalone error screen. Join that hotspot from a phone: the screen must advance to step 2 with the hotspot controller address/QR, even while router connection retries continue. Open the controller and reconfigure Wi-Fi. Disconnect/rejoin the hotspot and confirm the expected step transitions; restore the original network afterwards. Existing controller/standby behavior must remain intact. In the Demo, the removed failure option must be absent and its old `?scene=WIFI_FAILED` link must show JOIN. Finish with version/healthy confirmation and one temporary-manuscript play/pause/return check. No functional checks were run by the developer for this image.

## November 20 private-build evidence review / 本轮外部复核

The exact private-deployment .10 image subsequently passed local-file AP OTA, healthy boot observation, two separate 20-minute runs, all six injected queue failures, ordinary queued operations, and core playback/manuscript checks. No crash signatures or original manuscript loss were found in the submitted evidence. Required-update return handling and narrow layouts passed isolated HTML checks, not native-phone tests. This does **not** validate the separately compiled public BIN.

Remaining risks: fresh Web Bluetooth connections succeeded 4/5, with the first attempt timing out at 45 seconds; native discovery eventually succeeded 6/6 but one total took 47 seconds. Refresh did not reconnect automatically within 15 seconds; a manual connection recovered. Runtime jitter peaks near setting changes were 144/184 ms, and startup preview correction was observed; no physical screen video exists. Real phone background/lock and router-STA paths remain untested this round. Date text can truncate at 40px header font on an 800px-wide screen. Original content/styles/IDs/order survived, although the ordering revision changed.

For a limited trial, prefer the tested hotspot workflow and verify the actual recipient's phone, physical screen for 5–10 minutes, and background/return behavior. If Bluetooth is the sole control path, require repeated fresh connections and recovery first; do not describe the present evidence as unconditional Bluetooth acceptance. Do not make last-minute untested firmware changes merely to label a build stable. An existing .10 installation does not need reflashing for a documentation revision.

2. On mobile, check factory reset at the left and save at the right in Chinese and English, light/dark. Do not actually reset valuable settings for a layout check.
3. With a temporary manuscript, enable loop and header state. Expect `循环次数：0` / `Loop count: 0`, then increasing completed counts. The red dot before playing should visibly alternate bright/dim; countdown, paused, stopped and standby must not show a playing dot.

Success follows submission order, with correct placeholder geometry and no duplicates. Inject a failure for only the first A read, then restore successful requests: all already queued B/C jobs must cancel, C must remain, and no later write may replay. 5. Required update: use the virtual Demo `/console.html?update=required` first. 8. Measure full HTML load, a small API request, library and cold/warm preview on hotspot and router LAN, with and without internet. Reader font should fall back locally and use cache. Cover duplicate SSIDs with strong/weak APs if possible.
9. Check mobile background/lock, page exit/re-entry, two controllers, BLE reconnect and actual device reboot. Reading state should recover without unintended playback or rewind. Confirm header/footer controls stay editable over LAN and BLE.
10. Restore all changed settings, remove only the temporary manuscripts, and confirm original text, styles, IDs and manual order are intact. Never format SD or reset all configuration as a cleanup step.

Report firmware version, browser/OS, transport, steps, expected vs actual, screenshot/video, console/serial logs and settings restored. Do not include Wi-Fi passwords, tokens, private manuscript text or operator credentials in a public issue.
